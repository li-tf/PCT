# 固定水平台偏差专项审计

## 1. 问题与结论

本审计检查当前约`+1.4%`水平台偏差是否由配对、过滤、MLP、坐标变换、
DDB-FDK、OS-SART或ROI评价中的程序错误造成。

结论是：**没有证据表明该固定偏差来自重建实现错误；偏差已经存在于
`KineticEnergy → WEPL`转换后的单质子测量中。** 当前Python向量化LUT正确复现
项目C++ `pctBetheBlochFunctor`，但这个简化Bethe--Bloch水射程模型与
OpenGATE/Geant4的实际水输运射程不完全一致。因此它属于可修正的WEPL标定/前向
物理模型失配，而不是OS-SART数值错误，也不能据此直接否定当前MLP迭代框架。

## 2. 逐层证据

| 环节 | 审计结果 | 与`+1.4%`偏差的关系 |
|---|---|---|
| ROOT与primary配对 | 入口能量中位数为200 MeV，方向范数为1；按RunID/EventID/TrackID匹配并显式保留TrackID=1，既有ROOT与pair数量QC通过 | 未发现能量槽、单位或主质子身份错误 |
| Python WEPL LUT | 与正式ITK/C++ LUT抽样最大差`0.000182 mm` | Python移植误差远小于1.4% |

| S6水薄板 | 200 MeV、5--100 mm Water的原点约束斜率为`1.013518` | 不经过CT重建已经出现`+1.352%`比例 |

## 3. 为什么这不是普通的代码bug

当前WEPL定义为

\[
b_p=R_{\mathrm{BB},78}(E_{\mathrm{in}})
    -R_{\mathrm{BB},78}(E_{\mathrm{out}}),
\]

其中\(R_{\mathrm{BB},78}\)来自项目C++中以`I=78 eV`构造的简化Bethe--Bloch
积分。Python和C++给出相同结果，说明程序执行了设计中的模型。

OpenGATE使用Geant4完整输运，其能损、密度效应、涨落和射程定义并不等价于上述
简化积分。对物理厚度为\(L_p\)的均匀水路径，当前数据实际满足近似关系

\[
b_p \simeq 1.0135\,L_p+\varepsilon_p.
\]

任何以数据一致性为目标的正确重建器都会恢复约`1.0135`的水平台；强行要求
OS-SART输出1反而会增加WEPL残差。因此问题位于测量标定层，而不是求解器层。

## 4. 对当前算法评价的影响

阶段4仍然证明了迭代调度和Huber-TV能够显著降低噪声，并保持MTF与WEPL数据
一致性；这些结论仍成立。但当前绝对RSP准确性同时受到WEPL标定失配限制。

一个仅用于诊断的统一比例`1/1.013518`会把S4阶段4的15 mm大柱MLIC-MAPE从
`1.1987%`降至约`0.2002%`。这不是可发表的校正结果，因为比例来自同一批仿真，
且真实射程误差随能量变化，不能用一个常数覆盖所有质子和材料；它只证明WEPL
标定很可能是当前材料平台误差的主导因素之一。

## 5. 正确的后续修正

后续不应直接给重建图乘经验比例，也不应通过重新扫描TV或松弛因子吸收该误差。
更严谨的顺序是：

1. 建立与OpenGATE/Geant4一致的水射程—能量标定曲线，覆盖实际出口能量范围；
2. 用独立水厚度或能量case拟合，保留独立验证case，避免测试泄漏；
3. 将新射程表直接用于逐质子
   \(R(E_{\mathrm{in}})-R(E_{\mathrm{out}})\)，重新生成WEPL；
4. 先在S2/S3验证水平台和固定验证WEPL，再只重建S1、S4、S5确认材料与MTF；
5. 新旧LUT并列保存，历史结果不覆盖。

在完成这项独立标定前，不能把S4约`1.19%`MAPE全部解释为MLP或迭代算法能力
不足；同样也不能声称简单比例校正后的约`0.20%`就是最终性能。

## 6. 审计限制

本次没有重新执行昂贵的全量GPU重建。当前会话的CuPy运行时报告CUDA驱动不足，
因此新增的精确路径比例检查使用与CUDA公式对应的CPU Schulte MLP；历史正式
GPU伴随测试、检查点和验证结果保持不变。正式开始阶段7 GPU工作前需要先恢复
CUDA运行环境。
